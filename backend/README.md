# Odd Frequency Archive Backend

This directory contains the progressive server-backed foundation for Odd Frequency Archive. The public GitHub Pages site continues to work without it; the Worker activates shared features when configured.

## Architecture

- Frontend: existing static GitHub Pages files.
- API: Cloudflare Workers module at `backend/src/index.js`.
- Database: Cloudflare D1 migrations in `backend/migrations/`.
- Future evidence media: Cloudflare R2 binding `EVIDENCE_BUCKET`.
- Live updates: initial implementation uses polling; SSE/WebSocket can be added later if a Durable Object is justified.
- Public submissions: accepted only into `pending` moderation state.
- Admin actions: backend-enforced bearer token, not frontend-only hiding.

## Local Setup

1. Install backend dev dependencies:

   ```powershell
   cd backend
   npm install
   ```

2. Create a real Wrangler config from the example:

   ```powershell
   Copy-Item wrangler.toml.example wrangler.toml
   ```

3. Create local secret values:

   ```powershell
   Copy-Item .dev.vars.example .dev.vars
   ```

4. Create a local D1 database with Wrangler, then update `wrangler.toml`:

   ```powershell
   npx wrangler d1 create odd-frequency-archive
   ```

5. Apply migrations and seed data:

   ```powershell
   npm run migrate:local
   npm run seed:local
   ```

6. Run the API locally:

   ```powershell
   npm run dev
   ```

The frontend can point at local Wrangler by setting `localStorage.oddApiBaseUrl = "http://localhost:8787"` in the browser console. If the API is unavailable, the site uses local fallback data.

## Deployment

1. Create Cloudflare D1 and R2 resources manually in the Cloudflare dashboard or with Wrangler.
2. Copy `backend/wrangler.toml.example` to `backend/wrangler.toml`.
3. Replace placeholder D1 database ID and R2 bucket name locally.
4. Set secrets with Wrangler:

   ```powershell
   npx wrangler secret put ADMIN_TOKEN
   npx wrangler secret put TURNSTILE_SECRET_KEY
   ```

5. Apply remote migrations:

   ```powershell
   npm run migrate:remote
   ```

6. Deploy:

   ```powershell
   npm run deploy
   ```

7. Configure the frontend API base URL by setting `window.OFA_API_BASE_URL` before `js/ofa-api.js`, or use `localStorage.oddApiBaseUrl` during testing.

## Security and Privacy Notes

- CORS is restricted to official OFA origins and localhost development origins.
- Visitor identity is an opaque random local ID generated by the frontend.
- The API hashes visitor IDs before storing event/contribution records.
- Full IP addresses are not stored by application tables.
- Input is length-limited and sanitized before storage.
- SQL uses D1 prepared statements and bound parameters.
- Public submissions never publish immediately; they remain `pending`.
- Admin endpoints require a server-side `ADMIN_TOKEN`.
- Rate limiting uses hashed buckets in D1 where available.
- Reward/objective endpoints accept idempotency keys to reduce replay/duplicate effects.
- Turnstile hooks are documented but optional until configured.

## API Documentation

Base path: `/api/v1`

- `GET /health` - API health, version, DB/R2 binding presence.
- `GET /config` - public feature availability.
- `GET /signal/today` - shared Signal of the Day with local-compatible fields.
- `GET /condition` - current Global Archive Condition.
- `GET /weather` - current shared archive weather.
- `GET /activity` - privacy-safe live activity feed.
- `POST /events` - rate-limited event intake for popup closes, radio tunes, alchemy attempts, room opens, and echoes.
- `GET /popup-graveyard` - aggregate popup closure counts by popup type.
- `GET /objectives` - daily/shared objectives.
- `GET /creature` - shared Archive Creature state.
- `POST /creature/feed` - feed the creature with fictional junk items.
- `GET /alchemy/recipes` - server-rotating and community recipe hints.
- `POST /alchemy/record` - record a community recipe attempt.
- `GET /cases` - fictional case index.
- `GET /cases/:id` - fictional case details and fragments.
- `POST /cases/:id` - submit an in-story conclusion.
- `POST /submissions` - moderated creative submission intake.
- `GET /admin/submissions` - protected moderation queue.
- `POST /admin/condition` - protected condition update.
- `POST /admin/weather` - protected weather update.

All error responses use:

```json
{
  "ok": false,
  "error": {
    "code": "machine_code",
    "message": "Readable message",
    "detail": {}
  }
}
```
